# Бот-посредник Royal Snow (Telegram + Cloudflare Workers)

Клиент нажимает «Старт» в боте → бот создаёт для него тему в группе менеджеров → менеджеры отвечают в теме, а бот пересылает ответ клиенту от своего имени. Заявка с формы сайта приходит менеджеру карточкой в теме. Сервер не нужен, Cloudflare бесплатный.

**Режим: Б (форма с данными).** Сайт сохраняет заявку в своей базе и после отправки ведёт клиента по ссылке `t.me/<бот>?start=lead_<номер>_<подпись>`. Когда клиент нажимает «Старт», бот забирает заявку у сайта (`/api/lead/pull`, нужен секрет) и кладёт карточку в тему. Для этого у сайта должна быть подключена база (на VPS с Docker она есть; на Vercel — только с внешней PostgreSQL).

```
форма → POST /api/leads → сайт сохраняет заявку и возвращает botLink
клиент → «Старт» в боте → Worker: GET <сайт>/api/lead/pull?token=… (заголовок x-pull-secret)
Worker → тема в группе + карточка заявки; клиенту: «Заявка получена»
менеджер пишет в теме → бот копирует сообщение клиенту; сообщение с точки («.заметка») клиенту не уходит
```
Состояние бота (тема клиента, согласие, обработанные заявки) хранится в Cloudflare KV.

## Что нужно сделать (по шагам, без программирования)

1. **Создать бота.** В Telegram найдите **@BotFather** → `/newbot` → придумайте имя и логин (заканчивается на `bot`). Сохраните выданный токен, никому его не пересылайте и не публикуйте.
2. **Группа менеджеров.** Создайте группу → в настройках включите **«Темы»** (Topics) → добавьте бота **администратором** с правом **«Управление темами»**. Узнайте id группы (вида `-100…`), например через бота **@getidsbot** (добавьте его в группу, возьмите id, удалите бота).
3. **Cloudflare** (карта не нужна): [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages → Create → Worker** → **Deploy** → **Edit code** → вставьте весь файл `bot-cloudflare/worker.js` → **Deploy**.
   - **Хранилище:** Storage & Databases → **KV** → Create namespace (любое имя) → в Worker: Settings → Bindings → Add → KV namespace, имя привязки строго **`KV`**.
   - **Переменные:** Settings → Variables and Secrets:
     | Имя | Тип | Значение |
     |---|---|---|
     | `BOT_TOKEN` | Secret | токен от BotFather |
     | `WEBHOOK_SECRET` | Secret | любая длинная случайная строка (латиница и цифры) |
     | `GROUP_ID` | Text | id группы, `-100…` |
     | `SITE_URL` | Text | адрес сайта, например `https://ваш-домен.ru` (без слэша в конце) |
     | `CONSENT_URL` | Text | `https://ваш-домен.ru/soglasie` |
     | `PULL_SECRET` | Secret | секрет сайта (см. шаг 5) |
     | `GREETING` | Text | необязательно: свой текст приветствия бота |
4. **Подключить бота к Worker (один раз).** Откройте в браузере `https://<имя-worker>.workers.dev/setup?secret=<WEBHOOK_SECRET>`. Должно вернуться `"ok": true`. Если `workers.dev` не открывается, сделайте это с телефона по мобильному интернету или через VPN.
5. **Сайт.** Придумайте секрет (в терминале: `openssl rand -hex 24`) и задайте в окружении сайта:
   - `LEAD_PULL_SECRET` — этот секрет (тот же вписать в `PULL_SECRET` у Worker);
   - `BOT_USERNAME` — логин бота без `@`.
   На VPS: добавьте в `.env` и выполните `docker compose up -d`. На Vercel: Settings → Environment Variables → Redeploy.
6. **Проверка.** Отправьте заявку с сайта → вас перекинет в Telegram → нажмите «Старт» → в группе появится тема с карточкой. Ответьте в теме — сообщение придёт в бот. Сообщение, начатое с точки, клиенту не уходит.

Пока `BOT_USERNAME` или `LEAD_PULL_SECRET` не заданы, сайт работает как раньше (без перехода в бота).

## Важно
- **Прямое уведомление сайта в группу** (переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` на сайте) продолжает работать как страховка: менеджер узнаёт о заявке, даже если клиент не нажал «Старт». Если нужно только через бота, задайте на сайте `LEAD_NOTIFY_DIRECT=off`.
- **Согласие.** В форме чекбокс (не отмечен по умолчанию) со ссылкой на `/soglasie` и политику. Тексты — шаблоны, их нужно согласовать с юристом до запуска. Для тех, кто пришёл в бота не с формы, бот просит согласие кнопкой.
- Секреты (`BOT_TOKEN`, `WEBHOOK_SECRET`, `LEAD_PULL_SECRET`) вводите только в настройках Cloudflare и в `.env` сервера. В код, чат и репозиторий их не добавляйте.
- Услуги бота заданы в `TARIFFS` в начале `worker.js` (ключи совпадают с формой сайта). Цен нет намеренно.

## Автонастройка Cloudflare через Claude в Chrome (по желанию)
Если установлено расширение Claude в Chrome и вы вошли в Cloudflare, можно дать ему такой промт (значения секретов вводите сами, Claude их видеть не должен):
```
Открой dash.cloudflare.com → Workers & Pages → Create Worker, назови его royal-snow-bot, нажми Deploy, затем Edit code и вставь содержимое файла worker.js, который я открою рядом, и нажми Deploy. Создай KV namespace royal-snow-kv и привяжи его к Worker под именем KV. Затем в Settings → Variables and Secrets создай переменные: BOT_TOKEN (Secret), WEBHOOK_SECRET (Secret), PULL_SECRET (Secret) — на этих трёх остановись и дай мне самому ввести значения; GROUP_ID, SITE_URL, CONSENT_URL (Text) — значения я продиктую. После сохранения покажи адрес Worker.
```
